Plan rev 7, executed 2026-11-07 (revs 1-6 reviewed by Codex, 12 + 9 + 6 + 1 + 1 + 1 findings applied; round 6 returned no Major findings, see the log). Stacks on PR A (`feat/bbox-import-a-handoff`, PR #1848); branch `feat/bbox-import-b-fields` from that branch, worktree `/mnt/c/Wildbook-bbox`.

**Goal:** Let a bulk-import spreadsheet carry, per photo slot, a user-supplied box with its class and metadata; validate it in three layers with the existing error contract; create a real box annotation per boxed slot at import; stamp the import so PR A's hand-off extracts and identifies the boxes instead of detecting.

**Architecture:** Five new indexable field names (`Encounter.mediaAsset#.bbox|iaClass|viewpoint|theta|bboxSource`) join `BulkValidator.FIELD_NAMES_INDEXABLE` and are parsed in `validateValue`. `BulkImportUtil.validateRow` gains the per-slot row rules (pairing, class from a derived matchable list, duplicate photo in a row). `BulkImport.doPost` gains an import-level pass over the boxed files, in both modes, that writes its findings into the validated row maps before the existing error aggregation: header-only dimensions, bounds, cross-row consistency, duplicate boxes, a warning for un-boxed photos. A boxed import stamps `annotationsImported` from the server's own predicate, never detects and still hands off. `BulkImporter.processRow` creates a bounding-box feature and a matchable annotation per boxed slot, reading per-slot metadata (single keyword, `.keywords`, labeled keywords, quality) by exact slot number for the whole import when any row carries a `.bbox` column. `IAJsonProperties` derives the stored and matchable class lists; `SiteSettings` publishes them and the indexable field names so the page (PR C) and the skill (PR D) agree with the server.

**Tech Stack:** Java 17, DataNucleus JDO (`Shepherd`), JUnit 5 + Mockito (`mockConstruction(Shepherd.class)` harness as in `BulkGeneralTest` / `BulkImagesTest` / `BulkImporterMissingAssetTest`), `TestIAJsonPropertiesUtil.override` for IA.json fixtures, Testcontainers PostgreSQL (`IdentificationDbTestSupport`), ImageIO, metadata-extractor 2.6.2 (already a dependency), org.json.

**Spec:** `docs/superpowers/specs/2026-11-06-bulk-import-annotation-bboxes-design.md` (rev 8), sections 4.1, 4.2, 4.3, 4.5, 4.6 (capability signal only) and the PR B row of section 5; decisions 1 (pixel `x,y,width,height` only), 2 (class always required), 3 (unmatchable classes rejected unless identification is skipped), 8 (a boxed import never detects). ## Global Constraints

- Wire format: `Encounter.mediaAsset{N}.bbox` = `x,y,width,height`, four integers, comma separated, whitespace tolerated, `x,y >= 0`, `width,height >= 1`, pixel coordinates of the stored image's raw grid, origin top-left; a whole-photo box is allowed. The validator's value is the canonical string `x,y,width,height` (no spaces); the importer parses it to `int[4]`.
- `.iaClass` is required on every boxed slot (decision 2); the class must be in the species' matchable list unless the request skips identification (`skipIdentification` or `skipDetection`), in which case any canonical stored class is accepted (decision 3). No defaulting.
- `.viewpoint` optional, `Annotation.isValidViewpoint`; `.theta` optional, finite, `-6.2832 <= theta <= 6.2832`, radians, default 0, positive = clockwise as displayed, bounds apply to the un-rotated box, no clipping; `.bboxSource` optional, trimmed 1-128 characters; `Encounter.quality{N}` finite (NaN/Infinity now rejected for every row).
- Stored (canonical) classes for a species = `getValidIAClassesIgnoreRedirects(taxy)` (the user-selectable keys, as the manual-annotation page offers them) plus every redirect target: for each class key K under the species (non-`_`, not `common_name`/`match_trivial`/a `_subspecies` entry) the string at `get(<tax>.K._save_as)` when present, and the string at `get(<tax>._default._save_as)` when present (`get` follows `@` links; these are the two lookups `convertIAClassForTaxonomy` makes, read directly because that method logs four lines per call). Matchable classes = stored classes whose `identOpts(taxy, cls)` is non-null and holds an option with `optBoolean("default", true)` (intake's rule; `getIdentConfig` falls back to `_default._id_conf`, so a stored class with no key of its own is matchable through that fallback). Both lists are sorted and deduplicated.
- Capability signal: site setting `bulkImportIndexableFields` = `BulkValidator.FIELD_NAMES_INDEXABLE` sorted; `bulkImportMatchableClasses` = scientific name -> matchable list.
- The five suffixes are reserved: a configured keyword label equal to one is dropped when the labeled-keyword map is built, with a WARN; `StartupWildbook` builds the map at startup so the WARN is a startup warning (spec 4.1).
- One box per slot per row; a second animal on the same photo is a second row naming the same file; the same photo twice in one row, when either of those slots is boxed, is `INVALID_DUPLICATE` on the later slot (scanning every bare photo slot of the row, boxed or not).
- Exact-slot semantics: when any row of the import carries an `Encounter.mediaAsset#.bbox` field (even with an empty value), EVERY row reads `Encounter.keyword{N}`, `Encounter.mediaAsset{N}.keywords`, labeled keywords `Encounter.mediaAsset{N}.<label>` (cached separately from ordinary keywords, keyed by the (label, value) pair) and `Encounter.quality{N}` by exact slot N; other box suffixes alone do not switch the mode; imports without a `.bbox` field keep today's positional behavior, in which labeled keywords are validated and then not imported, exactly as today.
- The boxed-import predicate is ONE thing, computed by the server: `annotationsImported` = at least one validated row holds a `BulkValidator` for a `.bbox` field whose `valueIsNull()` is false. `initializeImportTask` writes `ImportTask.PARAM_ANNOTATIONS_IMPORTED` from that predicate on every import, overwriting any client-supplied value. A boxed import never detects (decision 8): the completion branches write status `imported` (not `complete`) and call `initiateIA` regardless of the skip boxes, with the user's `skipIdentification` (still implied by `skipDetection`); `initiateIA` is unchanged: it sets `processing-detection` and hands off exactly as for an ordinary import (the envelope PR A builds for a stamped task carries only box ids, and PR A's accessors report detection skipped), and its early return when no media survived creation is kept (nothing to extract; status stays `imported`, no IA task). When un-boxed media survive but every boxed file failed, the hand-off still runs and PR A's zero-box handling completes the root. Un-boxed photos in a boxed import are imported untouched (trivial annotation) and counted in a warning. A sheet with box columns and no values is an ordinary import.
- Validation parity: `validateOnly` performs every check that does not require decoding the full image: field, row, and for files referenced by a boxed slot: `Util.fastFileValidation`, header dimensions, bounds, cross-row consistency, duplicates. Each uploaded file is checked once (validity and dimensions cached per filename and reused by the existing file loop). A header-readable file that fails full decoding (`AssetStore.isValidImage` false) passes validation and fails at MediaAsset creation as today, and the importer skips that slot with its box.
- Tolerant imports (`tolerance.failImportOnError: false`; API-only, the page never sends `tolerance` and the default is true): the existing file loop runs only when `dataErrors` is empty, so today a tolerant import with any row error creates zero media. Because the boxed-file pass now adds row errors before that loop, the loop's condition becomes `!validateOnly && (dataErrors.length() == 0 || !toleranceFailImportOnError)`: in the default strict mode nothing changes (errors end in a 400 either way); in tolerant mode files are now validated and created despite row errors, a file the boxed pass already rejected is skipped without a second error, and un-cached files get today's `INVALID_IMAGE` check. Recorded as a deliberate change limited to tolerant imports. `tolerance.skipRowOnError` is parsed but never applied by today's code, so under tolerance a row whose box was rejected still imports its photo un-boxed, as any other rejected field behaves. Found while testing that path: today's aggregation assigns the default submitter only to valid rows, so an invalid row that reached the importer under tolerance threw "no value for Encounter.submitterID" and killed the whole import; the default is now assigned to every row whose sheet has no submitter column (a rejected submitter value keeps its error; strict mode unaffected: such rows end in a 400). Recorded as the second deliberate tolerant-mode change.
- Provenance marker on the feature: `_bulkImportBbox: {importTaskId, source?, scoreSource?, created}` (`Annotation.FEATURE_PARAM_IMPORTED_BOX`); `scoreSource` = `"detector"` when the slot's quality is set.
- Box construction guard: the importer builds an imported box only when the slot's `.bbox` AND `.iaClass` validators AND the row's `Encounter.genus` AND `Encounter.specificEpithet` validators are all present in `fmap` with non-null values; the box's taxonomy is `Util.taxonomyString(genus, epithet)` from those row values, never the encounter's own taxonomy (an encounter reused through `getOrCreateEncounter` keeps a taxonomy from an earlier row, and `Util.taxonomyString` yields a genus-only string when the epithet was rejected and dropped); otherwise the photo is imported as a trivial annotation, the validation errors already reported stand, and the computed `annotationsImported` flag is left as computed. The class is never defaulted (decisions 2 and 3). In the default strict mode this guard is unreachable (any such error ends in a 400); it matters under tolerance, where `createImport` drops exception fields before `processRow` and would otherwise hand a classless box to the constructor.
- Boxed annotation: `new Annotation(taxonomyString, feature, iaClass)` (the constructor adds the feature), `feature.setAnnotation(ann)`, `acmId = id`, `matchAgainst = true`, `wbiaRegistered = FALSE`, `wbiaRegisterAttempts = 0`, `isExemplar = true` (today's trivial annotations are exemplars), `skipAutoIndexing = true`, viewpoint and quality from the slot, `identificationStatus` left null; the asset's `detectionStatus` is left unset (PR A settles it). `FeatureType.load("org.ecocean.boundingBox", shepherd)` once per importer. Boxed annotations are added to `needIndexing` for `bulkOpensearchIndex` (collected from the encounters, no extra field). A feature-based annotation is never trivial under `Annotation.isTrivial()` (its legacy width/height stay 0, which that method treats as non-trivial), so a whole-photo imported box stays a non-trivial, matchable annotation and no consumer of `isTrivial()` changes.
- Errors use the existing `BulkValidatorException` types (`TYPE_INVALID_VALUE` / `TYPE_REQUIRED_VALUE` / `TYPE_INVALID_DUPLICATE`) through the four-argument constructor `(message, errorCode, type, fieldName)` so `getErrors()` entries carry `type` and `fieldName`; every import-level finding is written into the validated row map under its field name, so the existing aggregation adds `rowNumber`, counts the row invalid, and `BulkImportTableReview` needs no change. Warnings use the existing `dataWarnings` array with `type`.
- Recorded choices beyond the spec's letter: `Annotation(tx, ...)` and `isExemplar = true` follow the importer's existing conventions; the response carries `annotationsImported`; the warning type literal is `UNBOXED_PHOTOS`; the row rule resolves the taxonomy with `new Taxonomy(sciName)` instead of `myShepherd.getTaxonomy` because IA.json keys on the scientific name only (`taxonomyKey`, `hasIA`, `identOpts`), the name was validated by `isValidTaxonomyName` two lines earlier, `SiteSettings` builds taxonomies the same way, and a per-row datastore lookup buys nothing (accepted by Codex, round 2).

## Review Focus

1. **A box whose right or bottom edge equals the image edge** (`x + width == W`): must be accepted; off by one here rejects every whole-photo box. Test in Task 5: `boxTouchingTheEdgeIsAccepted`.
2. **A photo named on two rows, boxed on one and not the other, in either order.** The un-boxed row's photo field gets the error, not the boxed one. Test in Task 5: `photoBoxedOnOneRowAndNotAnotherIsRejectedOnTheUnboxedRow`.
3. **A forged `annotationsImported` in the request body.** It must not survive: a client cannot suppress detection on an ordinary import. Test in Task 5: `clientSuppliedAnnotationsImportedIsOverwritten`.
4. **A boxed row whose photo fails full decoding at MediaAsset creation, in a tolerant import.** The creation error is reported, the slot and its box are skipped, the other rows import, the hand-off carries only the surviving boxes. Test in Task 5: `corruptBoxedPhotoIsReportedAndItsBoxDroppedInATolerantImport`.
5. **`Encounter.quality{N}` and keywords on an un-boxed row with slot gaps inside a boxed import.** They land on the slot with the same N, not on the next occupied slot. Test in Task 6: `unboxedRowWithSlotGapsKeepsItsKeywordsAndQualityInExactSlotMode`.
