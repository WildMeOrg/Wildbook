# Bulk-import bounding boxes, PR E: submissions API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Plan rev 4, executed 2026-11-08 (2026-11-07; revs 1-3 reviewed by Codex, 11 + 7 + 4 findings applied, see the log). Stacks on PR B (`feat/bbox-import-b-fields`, PR #1850); branch `feat/bbox-import-e-submissions` from that branch, worktree `/mnt/c/Wildbook-bbox`.

**Goal:** Let a third-party push through `/api/v3/submissions` carry the same per-photo box fields as the spreadsheet, validated by the same rules plus the submissions' own file and cross-row checks, and let a boxed draft reach PR A's hand-off (extraction, then identification unless import-only) instead of detection.

**Architecture:** `SubmissionValidator` accepts the five box suffixes and `Encounter.quality{N}`, scans photos by bare numbered slot after unsupported fields are removed, runs the shared row rules with the draft's skip flag, checks box bounds against dimensions that `SubmissionFiles.verify` now returns, and applies the image-reuse rules in a cross-row pass over the eligible uses; `SubmissionValueIssues` translates the new rejections into plain reasons. `Submission` gains a persisted `boxed` flag, `requestsAi()` and two phase views used by both status endpoints; `SubmissionJobs.enqueue` sets the flag from the approved report and stamps the ImportTask; `SubmissionImporter.execute` runs the row rules with the skip flag and leaves the task `pending-detection` whenever AI is requested; `SubmissionProcessing` dispatches on `requestsAi()` and builds its message through PR A's shared `IAGateway.buildImportEnvelope`. The capabilities endpoint advertises `rowFields.perMedia`; the OpenAPI document and `submit-sightings.md` describe the fields, the image-reuse rule and the boxed import-only semantics.

**Tech Stack:** Java 17, DataNucleus JDO (`Submission` mapped in `org/ecocean/submission/package.jdo`; production `datanucleus.schema.autoCreateAll`), JUnit 5 + Mockito (the existing `SubmissionValidatorTest` / `SubmissionValueIssuesTest` / `SubmissionProcessingTest` / `SubmissionsTest` harnesses), Testcontainers PostgreSQL (`SubmissionStoreDbTest`: `readyJob`, `enqueue`, `importedForAi`, `mutate`, `aiState`, `realImport`, `realShepherd`), `TestIAJsonPropertiesUtil.override`, `SubmissionFilesTest.png()` (a 2x2 PNG), `ImageFixtures` (PR B).

**Spec:** `docs/superpowers/specs/2026-11-06-bulk-import-annotation-bboxes-design.md` (rev 8) §4.9 and the PR E row of §5; decisions 2, 3 and 8 as PR B landed them. PR B facts this plan relies on: `BulkValidator.BOX_SUFFIXES`, `parseBbox(text, field)`, `canonicalBbox`, the validated `.bbox` value is the canonical string, `BulkImportUtil.validateRow(row, sh, identificationSkipped)`, the row rules' error placement (pairing errors on the present metadata column; a missing class on `.iaClass` when that column exists, else on `.bbox`; `INVALID_DUPLICATE` on a repeated bare slot when a box is involved), the row rules' messages (`"bbox must be x,y,width,height: "`, `"bbox must be four integers x,y,width,height: "`, `"bbox x and y must be >= 0: "`, `"bbox width and height must be >= 1: "`, `"invalid theta value: "`, `"theta must be a finite number of radians between "`, `"invalid viewpoint value: "`, `"iaClass longer than 64 characters"`, `"bboxSource longer than 128 characters"`, `"invalid quality value: "`, `"quality must be a finite number: "`, `"<field> needs a box in <bbox field>"`, `"box without a photo in this slot"`, `"a box needs an iaClass in <class field>"`, `"invalid iaClass '<c>'; valid classes for <sp>: a, b"`, `"invalid iaClass '<c>'; no matchable classes for <sp>"`, `"photo <name> is already in slot <n> of this row; ..."`), `BulkImportUtil.findIndexedFieldNames`, `IAGateway.buildImportEnvelope(ImportTask)` (PR A: `{annotationMode: "extract-then-identify", annotationIds: [...]}` when `annotationsImported()`, the ids filtered to annotations whose marker names `itask.getId()`; else `{mediaAssetIds: [...]}` from `getMediaAssets()`), `ImportTask.PARAM_ANNOTATIONS_IMPORTED`, `skippedDetection()`, `skippedIdentification()`.

## Global Constraints

- Accepted row fields: today's `SubmissionValidator.FIELDS`, `Encounter.mediaAsset{N}`, and new `Encounter.mediaAsset{N}.bbox|iaClass|viewpoint|theta|bboxSource` and `Encounter.quality{N}`, N in 0-199 (the same `(?:[0-9]|[1-9][0-9]|1[0-9]{2})` family); anything else stays `UNSUPPORTED_FIELD`. `Encounter.quality{N}` is accepted with or without a box (it sets the annotation's quality either way, as the spreadsheet route does).
- Photos are the bare numbered slots only, read AFTER unsupported fields have been removed: both scans use `BulkImportUtil.findIndexedFieldNames(copied.keySet(), "Encounter.mediaAsset")` (nulls skipped) in `validate`, and the normalized fields' keys in `execute`; a `.bbox` or `.iaClass` key is never a filename, and an unsupported `Encounter.mediaAsset1000000000` never reaches the slot helper (which grows a list to the index; that unbounded growth on the spreadsheet route is pre-existing and outside PR E: noted for a follow-up).
- Row rules are shared: `validate` and `execute` call `BulkImportUtil.validateRow(copied, sh, identificationSkipped)` with `identificationSkipped = !draft.requestsIdentification()` (`import-only` skips). The `.bbox` value survives `normalizedRows` and re-validation as the canonical string.
- Empty values of the new fields: the row envelope rejects JSON null (`SubmissionJson.rows`), so an empty cell arrives as `""`; PR B validates the five box suffixes to a null value for blank text. For a key with one of the five box suffixes, a null validator value is NOT "Provided value cannot be empty": `values` keeps the key with `""`, so the column survives normalization and re-validation (an empty `.bbox` column keeps PR B's exact-slot mode) while the draft stays un-boxed. Today's "cannot be empty" rule stays for every other field. `Encounter.quality{N}` keeps the shared validation unchanged: an unset quality is omitted from the row, and `""` is rejected (`UNPARSEABLE`, "must be a decimal number"), because the shared validator parses quality before any blank rule (`tryDouble("")` fails); accepting blank quality would be a shared-validator change outside this PR. An empty `.bbox` beside a class or theta is rejected by the shared rule (1) as `REQUIRES_FIELD` on those fields.
- Image reuse across rows is a pass over the eligible uses after every row validated. An eligible use = a bare slot whose value is a present filename and which is not an in-row repeat (the row's second use of a photo is reported as today, "Image is repeated in this row", and excluded). A use is boxed when its `.bbox` validator holds a value (key = canonical bbox + `"@"` + theta, theta from the validated `Double` else `0.0`, `-0.0` normalized to `0.0`) or when its `.bbox` was rejected (boxed with an unknown key: it counts for the mixed-use rule and is excluded from duplicate-box comparison; its own `INVALID_BOX` issue is already reported). Per filename with uses on two or more distinct rows: (a) if every use is un-boxed, every use after the first gets `DUPLICATE_MEDIA` "Use each image in one row only" (today's rule); (b) if uses are mixed, every un-boxed use gets `DUPLICATE_MEDIA` with the §4.2 message `photo <name> has a box on row <r> but none here` (r = the first boxed use's row index); (c) independently of (b), among the boxed uses with known keys, a key already seen on an earlier row gets `DUPLICATE_BOX` ("Identical box already on row <r>") on that row's `.bbox` field. Different boxes on the same photo across rows are allowed (one animal per row).
- Suppression is explicit, not blanket: the shared rules' `INVALID_DUPLICATE` exception on a bare media field that this validator already reported as an in-row repeat is skipped (the only new suppression); the existing location suppression stays; every other shared-rule exception is reported, so independent date and value errors on different output fields are untouched.
- File checks: `SubmissionFiles.verify(entry)` returns `int[] {width, height}` (what `inspect` already reads from the header); `inspect(Path)` returns `{mediaType, width, height}` as a `JSONObject` and keeps its own reader because it also needs the format name and the subsampled decode (accepted deviation from the spec's "shared helper" sentence: the header read is four lines and reopening through `Util.fastImageDimensions` would read the image twice). `validate` checks every box with a known key against its file's dimensions (long arithmetic, edge equality allowed): out of bounds -> `INVALID_VALUE` reason `BOX_OUT_OF_BOUNDS` on the `.bbox` field, message `box x,y,w,h exceeds image WxH`. `execute` re-validates, so the same checks run again at commit. No manifest fields are added.
- Issue reasons: `SubmissionValueIssues.REASONS` gains `INVALID_BOX`, `MISSING_CLASS`, `UNKNOWN_CLASS`, `INVALID_VIEWPOINT`, `INVALID_THETA`, `BOX_OUT_OF_BOUNDS`; `translate` maps PR B's messages by prefix: the three bbox families (`"bbox must be"`, `"bbox x and y"`, `"bbox width and height"`) -> `INVALID_BOX` (`<field> must be "x,y,width,height": four whole numbers on the image's pixel grid, x and y at least 0, width and height at least 1`); `"a box needs an iaClass"` -> `MISSING_CLASS` (`<field> is required when a box is supplied`); `"invalid iaClass '<c>'; valid classes for <sp>: a, b"` -> `UNKNOWN_CLASS` (`'<c>' is not a matchable class for <sp>; use one of: a, b`) and `"...; no matchable classes for <sp>"` -> `UNKNOWN_CLASS` (`'<c>' cannot be matched: <sp> has no matchable classes`); `"invalid viewpoint value"` -> `INVALID_VIEWPOINT` (`<field> is not a known viewpoint`); both theta families (`"invalid theta value"`, `"theta must be"`) -> `INVALID_THETA` (`<field> must be a finite number of radians between -6.2832 and 6.2832`); the pairing message, which starts with the field name (`<field> needs a box in <bbox field>`, matched as `legacy.startsWith(field + " needs a box in ")`, the required field read from the remainder) -> `REQUIRES_FIELD` (`<field> requires Encounter.mediaAsset{N}.bbox`); `"box without a photo in this slot"` -> `REQUIRES_FIELD` (`<field> requires Encounter.mediaAsset{N}`); `"iaClass longer than"` / `"bboxSource longer than"` -> `OUT_OF_RANGE` (`<field> must be at most 64 / 128 characters`); `"invalid quality value"` -> `UNPARSEABLE` (`<field> must be a decimal number`); `"quality must be a finite number"` -> `OUT_OF_RANGE` (`<field> must be a finite decimal number`). Messages never expose Java exception text.
- Accepted deviation (Codex branch round 1): the MISSING_CLASS message names the class field (`Encounter.mediaAsset{N}.iaClass is required when a box is supplied`) even when the issue sits on `.bbox` because the row has no class column; that is more useful than `<field>`.
- Capabilities: `rowFields.perMedia` = `BulkValidator.BOX_SUFFIXES` (the suffixes a numbered photo slot accepts); `rowFields.supported` gains the literal `Encounter.quality#`; `rowFields.indexedQuality` = `"Encounter.quality0 through Encounter.quality199"` (a convenience in the style of `indexedMedia`, not required by §4.9). The skill checks `perMedia` before preparing boxed rows.
- `Submission` gains a persisted `Boolean boxed` (`package.jdo` column `BOXED`, nullable; schema auto-creation adds the column to an existing table, no data backfill; a SQL NULL reads as false), `boxed(boolean)`, `isBoxed()`, `requestsAi()` = `requestsIdentification() || isBoxed()`. `imported()` sets `aiState = requestsAi() ? "pending" : "skipped"`; `getAiState()` returns `skipped` when `!requestsAi()`; `dispatch` eligibility uses `requestsAi()` (`pending()`'s JDOQL already keys on `aiState == 'pending'`). `aiPhase()` is the hand-off phase and now keys on `requestsAi()`: the `not_started` branch for a failed or uncertain record import applies when `requestsAi()` (its code and message unchanged); `unknown`/`failed` as today (unchanged); otherwise `{state: getAiState(), message: ...}` where the message is today's for an un-boxed draft that requests identification, `"Extraction and identification workflow handoff; dispatched does not mean completed. See import task for progress and match candidates."` for a boxed draft that requests identification, `"Extraction-only workflow handoff for the supplied boxes; identification is not run (import-only); dispatched does not mean completed. See import task for progress."` for a boxed import-only draft, and `"Explicit import-only mode"` when `!requestsAi()`. `detectionPhase()` = boxed ? `{state: "skipped", code: "BOXES_SUPPLIED", message: "Boxes were supplied; detection is not run on these photos"}` : `aiPhase()`. `identificationPhase()` = `requestsIdentification()` ? `aiPhase()` : (boxed ? `aiPhase()` plus `code: "BOXES_EXTRACTED_ONLY"` ONLY when the phase is a normal-operation one (`pending`, `dispatching`, `dispatched`; a `not_started`, `failed` or `unknown` phase is returned exactly as `aiPhase()` built it, code and message untouched) : `{state: "skipped", message: "Explicit import-only mode"}` as today). BOTH `Submission.json()` and `SubmissionJobs.results()` put `detection` = `detectionPhase()` and `identification` = `identificationPhase()`. The GET shapes keep their keys.
- `SubmissionJobs.enqueue` derives `boxed` from the approved validation's `normalizedRows` (`optJSONArray`: an old report without them is un-boxed; boxed = any row's `fields` key whose `BulkValidator.indexPrefixValue` is `Encounter.mediaAsset.bbox` with a non-empty string value), sets it on the draft before `queue(...)`, and stamps the ImportTask passed parameters with `annotationsImported: boxed`, `skipDetection: !requestsIdentification() || boxed`, `skipIdentification: !requestsIdentification()`. `SubmissionImporter.execute` sets the task status `pending-detection` when `draft.requestsAi()`, else `complete`.
